## 一、这个项目是什么

给 **Assetto Corsa Competizione（ACC）** 做一个外部程序：读游戏遥测，驱动 Xbox 手柄的**四个马达**——
两个握把 + 两个扳机。ACC 原生只震握把，扳机是空的。

核心目标是**让扳机告诉你轮胎到没到极限**（刹车抱死、出弯打滑）。
扳机马达更适合干这个：它贴指尖，反应快，而且不占握把的带宽。

完整设计在 `设计说明.md`，那份文件是决策记录，**改之前必须先跟用户确认**。

## 三、三条最重要的实测结论

### 1. 扳机只能走蓝牙 HID 报文

三条路都试过，只有 HID 真的能驱动：

| 通道 | 结果 |
| --- | --- |
| **蓝牙 HID 输出报文 0x03** | ✅ 可用，四马达全控，**不受前台焦点限制** |
| Windows.Gaming.Input | 能枚举、能写入、读回值也对，**但马达不响** |
| GameInput | 这台机器上**读不到任何设备**（连键盘鼠标都读不到） |
| XInput | 只能两个握把 |

报文格式（9 字节，值 0~100）：
`03 0F <左扳机> <右扳机> <左握把> <右握把> FF 00 EB`

### 2. 判断 HID 能不能发振动，必须"试写"，不能查能力

`HidP_GetCaps` 返回的 `OutputReportByteLength` 是 **0**，但直接 `WriteFile` 9 字节报文**能写进去、马达会震**。

原因：它只报**第一个顶层集合**（手柄输入）的能力，而震动报文在同一个设备的**另一个集合**里。

**正确做法**：打开设备后发一个全零报文，能写进去就算这条通道可用。
（参考项目 `asasiton/lmu-` 里那句 `OutputReportByteLength == 9` 的筛选也是猜的，会把可用设备筛掉。）

### 3. ACC 每帧重写四个马达，必须屏蔽它的写入

ACC 每帧调 `XInputSetState`，**一次重写四个马达，把两个扳机清零**。我们刚写的扳机震动被它下一帧冲掉 → 表现为"断续、强度不足"。

**把游戏内震动调到关闭也没用**——实测它仍然每帧发零值（关闭只影响"震多少"，不影响"发不发"）。

解法：`AC2\Binaries\Win64\` 放一个自编译的 `xinput1_3.dll`（`tools/xinput_proxy/`）：
读手柄的调用全部转发给系统那份，**只吃掉 `XInputSetState`**。

**效果**：赛道上扳机又稳又满，而且 **60Hz 就够**（120/200Hz 没有更好）。
→ 写入频率与遥测 333Hz 彻底脱钩。

## 四、ACC 字段的实测量纲（写代码直接用）

| 字段 | 实测结论 |
| --- | --- |
| `slipRatio[4]` | **float**（文档标 int 是错的）。无量纲，前轮 -1.0 = 完全抱死 |
| `wheelSlip[4]` | **弃用**。数值到 222，与"滑移比×车速"对不齐，含义不明 |
| `accG[3]` | **车身坐标，但轴序是 X=横向、Y=垂直、Z=纵向** |
| `kerbVibration` | ±0.1 截断，×10 才是 0~1 |
| `slipVibrations` | ±1 截断，62% 的帧都 >0.02 |
| `gVibrations` | 0~7.5，不截断，91.5% 的帧都 >0.02 |
| `absVibrations` | 只剩 ±1/0 的方波 = "ABS 正在动作" |
| `brakePressure[4]` | 不是 bar，是"刹车输入 × 前后分配比"：同轴左右相同，前+后=1。这次实测前 0.742 / 后 0.258（换车/改刹车平衡会变） |
| `gear` | 原始值从 0 起算：**0=R、1=N、2=1 档**、3=2 档……**换挡瞬间会短暂报 1（约 75ms）**。代码里 `gear_raw` 保留原值，`gear` 已减 1，`gear_label` 直接显示 R/N/数字 |
| `wheelLoad[4]` | 停车时读出来全是 0（旁边胎压 25.8/26.4 psi、胎温 70+℃ 都合理，说明偏移没错）。**行驶时是否非零还没验**，左右路肩的分配依赖它 |

`accG` 轴序的证据：corr(accGx, 车速×横摆角速度/9.81) = **-0.927**；
直线重刹时 accGz 平均 **-1.61**，全油门加速时 accGz 中位 **+0.47**。
**按字面理解会把刹车读成横向。**

## 七、已经踩过的坑（别重犯）

1. **`HidP_GetCaps` 假阴性** —— 见第三节第 2 条。判断能力要试写。
2. **WGI 的设备列表是延迟填充的** —— 第一次查 0 个，等 1 秒就有。
   **任何探测都必须轮询重试**，查一次就下结论会得出完全错误的判断（我因为这个错了两次）。
3. **代理 DLL 的导出表序号** —— 系统那份 `xinput1_3.dll` 第 1 号是 `DllMain`，
   真正的函数从第 2 号开始。用 `.def` 必须显式写序号并逐个对齐，
   否则按序号取函数会拿到错的函数 → ACC 直接 UE4 fatal error。
   正确序号：`GetState@2`、`SetState@3`、`GetCapabilities@4`、`Enable@5`、
   `GetDSound@6`、`GetBattery@7`、`GetKeystroke@8`。
4. **官方 ACC 文档有三处错**：`slipRatio` 类型、四个震动通道类型、`accG` 语义。别照文档写。
5. **造测试数据时别用 `Local\acpmf_physics` 这个名字** —— `CreateFileMapping` 会复用
   ACC 正在用的那块映射，等于往游戏的数据里写真值（虽然被 333Hz 覆盖了，但很危险）。
6. **用 Python 生成 .bat 时，源码里的 `\\` 会被转义成 `//`**。
   用 `os.sep.join()` 拼路径可避免；或者直接用写文件的工具写，别过 shell 的 heredoc。
7. **Bash 里调 PowerShell 会被安全策略拦**，要用专门的 PowerShell 工具。
8. **`手感设置.toml` 里注释的数字不是值。** 第一次用户把注释里的"1.0 是基准"
   改成了 4.0，真正的 `grip_kerb = 1.35` 没动，所以怎么调都没反应。
   现在文件改成行内注释（`grip_kerb = 4.00  # 路肩`），程序启动和热更新时
   都会打印**实际生效的四个数**。

### 1. `pad_driver.py`（已完成）

全部依据都在阶段 0 验证过，硬指标：

- 用**试写**探测可用的 HID 通道，不要查 `HidP_GetCaps`
- 写入频率 **60Hz**；完全静止在 0 时不重发，只要有一个马达不是 0 就每拍都写
  （不做"值不变就少发"的优化：报文尾部的脉冲参数多久失效没确认过）
- **回零必须立即发**，不等下一拍；退出 / 异常时一定清零（`finally` / `atexit`）
- 手柄断连后能自动重连（蓝牙会掉）
- 单实例保护（两个写入者会互相打断）

### 2. `acc_telemetry.py`（已完成）

- 读 `acpmf_physics`，按显式字节偏移解析（**物理页 800 字节**，系统按页对齐给 4096 是正常的）
- 字段量纲照第四节的表，**别照官方文档**
- 提供"最新快照"接口，而不是逐帧回调（避免阻塞）

### 3. `haptics_engine.py`（已完成）

- 输入：遥测快照；输出：四个马达值
- 分层：底层压力反馈（≤20%）+ 上层临界事件（≤70%）
- 混音用加权求和 + 单次软限幅，遵守"1 主 + 1 辅"预算（见 D11）
- **注意**：前轮抱死是一帧到位的，没有渐变过程，"逼近时逐渐增强"做不出来，
  只能报"已经锁死"或做"ABS 正在救你"的嗒嗒（见第五节和 D5 的修正注记）

写的时候落下的几个细节（代码里有注释，这里记一笔）：

- **ABS 的节奏由我们自己出**（70ms 脉冲 + 120ms 不应期，约 8Hz），
  `abs` / `absVibrations` 只用来判断"ABS 在动作"。
  实测 `abs` 只有 0/1，而游戏方波的频率没保证；太快时 ERM 会把它抹成连续震动，
  听不出"嗒嗒"。
- **后轮打滑用 0.6 次方，不是 D8 的 4 次方。** 0.15 的硬阈值已经负责"平时安静"，
  阈值以上再压 4 次方会让刚打滑时几乎没有反馈。D8 的 4 次方留给没有硬阈值的连续量。
- **路肩的左右分开是启发式**：按左右轮荷差分给两侧分权重，基础 70/70，
  最大轮荷差时约 1.0 : 0.4（对齐 D7 的左右幅差）。压到的那侧一般更重，
  但弯道外侧也会更重，阶段 3 再校。
- **握把的路面纹理有死区。** `gVibrations` 91.5% 的帧 >0.02，不设死区就是永远在震。
- **点窗口 × / 注销 / 关机时**，`atexit` 不会跑；`pad_driver` 用 `SetConsoleCtrlHandler`
  抢一包零，点 × 关窗口也能清。
