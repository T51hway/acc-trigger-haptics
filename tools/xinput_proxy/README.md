# xinput1_3.dll 代理

## 为什么需要它

ACC 每一帧都会调用 `XInputSetState` 往手柄写震动，**而且它一次会把四个马达全部重写**——包括两个扳机，写成 0。

我们自己驱动扳机走的是蓝牙 HID 报文，两条路写的是同一组马达。结果是：我们刚写进去的扳机震动，被 ACC 下一帧清零。实测表现为"扳机震动断断续续、强度不足"，写得越快抢到的比例越多，但永远抢不全。

把 ACC 的游戏内震动关掉**也没用**——实测它仍然每帧发零值。

## 它做什么

游戏运行时会加载 `xinput1_3.dll`（这个字符串在 `AC2-Win64-Shipping.exe` 里找到的）。把同名 DLL 放到可执行文件旁边，游戏就会优先加载我们的版本。

- **读手柄的调用全部原样转发**给系统的真 DLL（`C:\Windows\System32\xinput1_3.dll`），输入完全不受影响
- **只有 `XInputSetState` 直接返回成功、不往下传**，ACC 的震动指令到不了硬件

整个文件 60 多行，见 `proxy.c`，没有别的行为。

## 怎么装 / 怎么卸

用仓库根目录的两个 bat：

- `开启接管.bat` → 复制到 `AC2\Binaries\Win64\`
- `恢复原生.bat` → 改名成 `xinput1_3.dll.off`

底层开关就是"这个文件在不在"，手动改名字效果一样。

## 自己编译

需要 MinGW-w64 的 gcc：

```
gcc -shared -O2 -static -o xinput1_3.dll proxy.c proxy.def
```

## 影响范围

- 只影响 ACC，因为文件在 ACC 自己的目录里，别的游戏加载不到
- **方向盘不受影响**：方向盘走 DirectInput 和 DirectInput 力反馈，跟 XInput 是两套独立通道
- 不改注册表、不装驱动、不动任何原有文件
- Steam 校验文件时会报 1 个文件异常，删掉 DLL 再校验即恢复
- ACC 大版本更新一般不会删它；如果震动突然又变断续，第一件事是看这个文件还在不在
